Getting started

  1. Start werkz in a project folder:

    cd ~/code/my-app
werkz

  2. Connect at least one provider. The first run opens the key screen. Paste any keys you have, press Ctrl+S to save and verify them, then Enter to start. No keys at all? Install Ollama, run ollama pull llama3.2 and press Esc. See Providers and models for where to get keys (and Getting an OpenCode Zen key for OpenCode Zen).

  3. Ask for something:

    ❯ explain how authentication works in this repo
❯ add pagination to the /users endpoint and update the tests
❯ why does `go test ./...` fail? fix it

  4. Approve the risky steps. werkz shows each command, and a preview of each edit as a diff, before running it. Choose with ↑/↓ and Enter: yes, yes and don't ask again this session, or no (also Esc: no, and tell werkz what to do instead).

What a session looks like#

❯ the login form accepts empty passwords, fix it and add a test

● Grep(password in src)
  ⎿  3 files
● Read(src/auth/login.ts)
  ⎿  Read 84 lines
● Edit(src/auth/login.ts)
  ⎿  +4 −1 lines
● Bash(npm test -- login)
  ⎿  exit 0
● Empty and whitespace-only passwords are now rejected before the API call, with a test covering both.

Make the most of it#

  • Type @ to attach a file or folder to your message: Mentioning files
  • Drag over any text in the conversation to copy it: Copying text
  • /resume (or werkz -c) continues an earlier conversation: Saved conversations
  • Ask werkz to check web UI it changed: it starts your dev server and uses Chrome: The browser
  • Add your MCP servers to use their tools: MCP servers
