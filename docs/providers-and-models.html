* Gemini and Groq are free only while the key's project has no billing, so werkz labels their models "free tier". OpenRouter's :free models are labelled "free", and Ollama "local".

OpenCode Zen is OpenCode's hosted models (Claude, GPT, Gemini, Kimi, DeepSeek, GLM, Qwen and more) under one key. /model lists its models with their prices, which werkz reads from OpenCode. OpenCode's free models aren't listed: OpenCode lets them answer only inside its own app.

Getting an OpenCode Zen key#

  1. Go to opencode.ai/console and sign in.
  2. Add your billing details and buy credits. Zen is pay as you go: each request is charged to your credits, at the prices /model shows. OpenCode adds a processing fee to each credit purchase, and can top your credits up automatically if you turn that on in the console's billing page.
  3. Copy your API key from the console.
  4. In werkz, run /login, move to OpenCode Zen, paste the key and press Ctrl+S to save and check it. Or set OPENCODE_API_KEY in your shell instead.
  5. Pick a model with /model: OpenCode Zen's models are listed under it, with their prices.

The key screen also shows where to get it: select OpenCode Zen and it says get a key → opencode.ai/console.

Add or change keys at any time with /login (or werkz --login). Keys are checked when you save them.

Using a subscription instead of an API key#

You can use the API and your subscription side by side, in one conversation: pick either from /model and switch whenever you like. werkz's browser, dev servers and your MCP tools work with both.

ChatGPT plan (Sign in with ChatGPT)#

/login chatgpt

werkz opens your browser to sign in to ChatGPT ("Continue with ChatGPT"). After you allow werkz to use your plan, models marked plan appear in /model, and requests to them count toward your ChatGPT plan's usage limits instead of being billed to an API key. On Plus that is a five-hour limit shared with your other apps; see or cap werkz's share at chatgpt.com/settings/usage. The status bar says Using ChatGPT plan while one of these models is selected.

  • This uses OpenAI's official Sign in with ChatGPT for open-source apps. werkz never reads the Codex CLI's login.
  • werkz's tools, permission modes and safety rules work exactly as with an API key.
  • The sign-in is stored in ~/.config/werkz/chatgpt.json (only your user can read it) and refreshed automatically. /logout chatgpt revokes it.
  • When the plan's limit is reached, werkz says so and links to the usage page; with fallback on, another model can take over.
  • Limits: OpenAI doesn't share plan usage with apps, so werkz can't always show it. /usage shows the 5-hour and weekly readings when ChatGPT's responses include them (the same readings Codex shows; this isn't documented by OpenAI), says clearly when the limit is reached, and otherwise links to chatgpt.com/settings/usage.
  • Over SSH or on a machine without a desktop, werkz shows the sign-in link instead of opening a browser. Open it on your computer; if werkz runs on another machine, first forward the port werkz names (for example ssh -L 1455:127.0.0.1:1455 your-server) so the sign-in can return to werkz.

Claude Code (your Claude subscription)#

Anthropic doesn't allow other apps to sign in with a Claude account, so werkz doesn't. Instead it can run your own installed Claude Code in its headless mode (claude -p): Claude Code uses its own sign-in and your subscription, and werkz shows its work.

  1. Install Claude Code and run claude once to sign in.
  2. In werkz, pick a model marked (Claude Code) in /model (/login claudecode checks the setup).

How it differs from the other providers:

  • Claude Code does the work with its own tools, and werkz shows each step. When Claude Code needs permission, werkz asks you with its usual dialog and rules (plan mode, folders, credential locations). Actions Claude Code's own settings already allow don't ask.
  • werkz lends Claude Code the tools it doesn't have: werkz's browser (open, read, click, type, scroll, screenshots, also in your own Chrome after /browser connect), DevServer and your MCP servers' tools. werkz runs these itself, so you watch the browser with /browser view and each call goes through werkz's own permission rules, as with any other model.
  • Claude Code keeps the conversation and compacts it itself; werkz's /compact and caching settings don't apply. Switching to Claude Code mid-conversation passes the conversation so far along. Switching from Claude Code to an API model passes along Claude Code's answers and the tools it used, with the start of each result (the latest three turns whole, older ones shortened), so the next model knows what was read, run and found. Like any tool result, that can include parts of files Claude Code read.
  • werkz removes ANTHROPIC_API_KEY from Claude Code's environment, so it uses your subscription rather than billing that key.
  • Limits: Claude Code reports your plan's usage windows with every request: the 5-hour window, the weekly window, and a model's own weekly window (such as Fable) when your plan has one. The status bar shows them (for example 5h 23% · weekly 24%), /usage lists each with its reset time, and werkz warns once as a window passes 80% and 90%.
  • This mode relies on Claude Code's documented headless mode; Anthropic's terms don't say whether running it from another app is allowed, so check them if that matters to you.

For the other providers, /model lists the models your key can use.

OpenRouter: free and paid models#

OpenRouter gives one key access to hundreds of models. By default werkz shows only its free (:free) models. Run /openrouter paid to also list the paid ones (Claude, GPT, Gemini, Llama and many more) with their real per-token prices; they're billed to your OpenRouter credit, which the status bar shows. /openrouter free hides them again. Paid models are labelled as paid everywhere werkz offers them, including the fallback dialogs.

Free OpenRouter models are withdrawn from time to time. werkz checks the live list at start-up and, if your free model is no longer offered, switches to an available free one and tells you.

Effort and fast mode#

  • /model switches between every connected provider's models, showing context size and price.
  • /effort sets how much the model thinks before it answers:
    • On Claude the levels are low, medium, high, xhigh and max. Higher is smarter, slower and costs more; xhigh suits hard coding work. The defaults are medium on Opus 5.5 and Haiku 5.5, and high on Sonnet 5.5 and Fable 5.2.
    • On other providers the levels are auto, low, medium and high.
  • Fast mode (Opus 5.5 and Fable 5.2) streams output up to about 2.5× faster, at double the price.

Changing the model, effort or fast mode in the middle of a conversation invalidates the prompt cache, so werkz warns you when you make the change, with what re-sending the conversation will cost. See Saving tokens and money.
